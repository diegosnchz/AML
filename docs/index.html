Detection Logic

Six Detection Typologies

Rule-based detection via dbt models, triggered by configurable thresholds aligned to AMLD5 and FATF guidance.

Smurfing
Sub-threshold transaction structuring to avoid reporting obligations. Multiple small transfers to distinct beneficiaries within a 72-hour rolling window.
Critical5+ txns <€9,999 / 72h
Fan-Out
Single account distributing funds to an anomalously high number of distinct beneficiaries in 24 hours — indicative of layering after initial aggregation.
High10+ beneficiaries / 24h
Fan-In
Account receiving funds from many distinct senders simultaneously — a classic aggregation hub, often followed by a single consolidating outbound transfer.
High10+ senders / 24h
Circular Flows
Funds cycling back to the originating account through a chain of intermediaries — a definitive signal of wash-trading or deliberate source obfuscation.
CriticalA→B→C→A within 7 days
Layering
Multi-hop transfer chain where each hop deducts a small commission (85–99% pass-through), obscuring the origin while preserving value across intermediaries.
High3+ hops · 85–99% each
High-Risk Geography
Transactions involving FATF-monitored jurisdictions: Iran, DPRK, Myanmar, Syria, Yemen, Haiti, South Sudan, Nigeria, Venezuela, and 6 further watchlist countries.
High15 FATF jurisdictions

Technology

Stack Breakdown

Each component chosen for production-grade AML monitoring at financial institution scale.

Orchestration
Airflow
  • DAG-based scheduling for all ETL and ML jobs
  • Auto-retry on ingestion failure with alerting
  • Daily incremental loads + full-refresh on demand
  • Docker Compose with Celery executor
Storage + Transform
PostgreSQL + dbt
  • 5-schema warehouse: raw → staging → features → alerts → ml
  • 78 dbt tests enforcing integrity and data quality
  • Incremental models for efficient daily refreshes
  • Alert staging with severity metadata and evidence
Graph Analytics
Neo4j GDS
  • PageRank to surface high-influence transaction nodes
  • Louvain community detection for ring discovery
  • Betweenness centrality for aggregation-hub flagging
  • In-memory graph projection for GDS algorithm runs
ML Scoring
XGBoost + SHAP
  • XGBoost best-performing across 5 benchmarked models
  • SHAP values for per-alert feature attribution
  • Graph features (PageRank, community size) as ML inputs
  • Risk score 0–100 written to alerts schema for triage
